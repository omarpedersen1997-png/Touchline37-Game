# Build 35 — reliable Android uploads and three new match features

The reported 5–1 save failure was reproduced at the native boundary: the Android plugin rejected requests longer than 8192 characters, while a completed 4-minute recording contains 13336base 64 characters before its JSON envelope. The native game POST envelope is now 16384UTF-8 bytes; other route limits and the URL/method whitelist are retained. A production Java policy test and a JVM harness around the actual plugin class verify complete engine 8 packets, exact bytes, cookie/session rotation, headers/status/errors and rejection before network access. The harness uses test-only Android/Capacitor/vault stubs and fake HTTPS, not a phone emulator.

Save reliability now includes a queued critical-write path, actual native/server error propagation, bounded retries for transient errors, automatic retry after busy clears/reconnection, and a matching canonical acknowledgement before deleting the recording. Pending current-match tapes survive their former local expiry. New versions 6+ receive 24h upload recovery; still-active old 6/7 challenges with the original deadline migrate once before settlement. Already-settled forfeits are not rewritten. No client score or reward is trusted.

Three new features:

1. Live match plans: three tactics and four formations recorded as strict high-bit engine 8 commands. They apply during play and halftime without teleporting players or changing the opposition's formation. Choices apply to this match, not the account's manager settings.
2. Real goal replays: bounded in-memory footage from actual engine states, genuine pre-kickoff goal crossings, smooth playback and a return to results. The latest three clips are available while the match view remains open. Old-engine footage is honestly labelled build-up. Replays never advance recorded controls or affect results.
3. Detailed match statistics: actual shots, saves, possession, team passing/tackles and personal contributions. Missing data stays blank rather than invented. Engine 8 has side-specific passing/tackle counters. Club and personal match results both remain open after acknowledgement for statistics/replays.

Smoothness changes also fix the render phase to use actual fixed-step match time, keep player prediction steady while limiting only the ball near contact, warm later detailed rigs/canvas textures in idle time, and move routine local saves outside the draw. Completion/background/exit saves still flush synchronously. No image-resolution reduction or physics-timestep change is used.

The existing closer fixed camera, pitch/environment detail, native-resolution Sharp rendering, efficient crowd/architecture/players and 30Hz frame pacing are retained. No extra per-frame shadow or image-processing pass is introduced. Replay capture is bounded and statistics/tactics stay inside match screens; the locked main app/marketing design and January 1 public gates are retained. Engine 1–7 physics remain immutable; engine 8 still uses two 120-second halves plus 10 seconds halftime and the same 5000-input/13336-character envelope.

Validation includes the full automated suite, web checks, actual native transport policy/plugin tests, deterministic tactical replay/API/retry tests, real-data stats/replay tests, Android compilation/signing/packaging, HTML equality and private HTTPS file verification. A live server timing/replay test uses temporary accounts which are deleted afterward. No physical-phone GPU/FPS/thermal/touch experience or browser screenshot is certified by these checks.
